>
> - **One lookup rewrote the layout every later card was built from.** The
>   layout table was handed out by reference and appended to.

## How this was done {#method}

Three audits ran in parallel over areas the earlier rounds had not touched —
the sources and network layer, the settings page and popup, the selection and
export paths — while the surfaces were driven and photographed by hand.

Every finding was then reproduced here before anything was changed. Two were
dropped at that step because they described behaviour the code does not have,
and two of the tests written to pin fixes failed first on the test rather than
the code, which is its own kind of evidence.

## What was wrong with a card before it was drawn? {#composition}

The layout table was shared, mutable, and appended to.

`layoutFor` returned `LAYOUT[intent]` itself; `createCard` stored that array
as the card's slot order; and `applyResult` pushes onto that order whenever a
provider fills a slot the layout did not anticipate. Every such push rewrote
the table for the life of the service worker.

```oku-annotated-code
{"src":"// Reproduced, then fixed\nlayoutFor('entity')  // entity facts onPage extract translation inContext links\n\nconst card = createCard('1', 'Mercury', 'entity');       // (1)\napplyResult(card, 'free-dictionary', { slots: { headword, senses } });\n\nlayoutFor('entity')  // … inContext links headword senses               // (2)\ncreateCard('2', 'Paris', 'entity').order  // … headword senses          // (3)","lang":"javascript","annotations":[{"id":1,"content":"<code>Mercury</code> routes as an entity and fetches word data alongside, so the dictionary answers with slots the entity layout never planned for."},{"id":2,"content":"The table itself now carries them. Not this card's copy — there was no copy."},{"id":3,"content":"So the next entity lookup, minutes later and about something else, is built with two slots no provider will fill. They are marked empty and drawn as blank rows below the links."}]}
```

Three more in the same area. Both dictionary sources answer per entry, so a
word with a noun entry and an adjective entry returned two UK pronunciations a
schwa apart and the card printed both — the reader asked how to say the word
once. The free dictionary was the only source not trimming the selection
before putting it in a URL, so a drag or a triple-click that carried a
trailing space returned 404 and lost the richest source on the card while the
others answered. And Wikipedia's unbiased retry assigned over the biased
result instead of falling back to it, so a refused retry — that endpoint
answers 429 readily — discarded an article already in hand.

## Why did the card say everything twice? {#twice}

"On this page" is a sentence the page uses to define the word. "Where you met
it" is the sentence the selection sat in. Looking a word up in the sentence
that defines it is the ordinary case, and the card printed that sentence
twice, under two headings, one above the other.

The higher block keeps it now, with the word marked inside it using the same
splitter the lower block used, so nothing is lost.

## Was the sentence even the right one? {#sentence}

No. The extractor searched the text for the selected string instead of using
the position the selection starts at, so it returned the first sentence that
mentioned the word rather than the one the reader was in.

```oku-compare-grid
{"cards":[{"t":"Selecting the second \"manifest\"","b":"In *A manifest lists data files. Each manifest belongs to a snapshot.* the card reported the **first** sentence. That string is what the card shows, what a note quotes, and what the senses are ranked against — three wrong answers from one search.","accent":"warn"},{"t":"After","b":"The range knows where it starts, so it is passed in and used. The search stays as the fallback for a container that is not a text node.","accent":"success","verdict":"good"}]}
```

Two smaller things in the same function. Only the full stop ended a sentence,
so *What is a manifest? A manifest lists the data files.* came back whole for
a selection in the second half. And prose with no terminator at all was cut at
exactly 300 characters, mid-word, in text that is shown to a reader and quoted
into their notes.

## What did holding the modifier take away? {#hover}

Hover lookup attaches its pointer listener while a modifier is held. Three
defects, all about releasing it.

- **A queued animation frame outlived the modifier.** Deactivating removed the
  listener and cleared the dwell timer but never cancelled the frame, and the
  callback did not check whether it was still wanted. Letting go mid-movement
  resolved a word, painted the overlay for it, and opened a card 220 ms later
  for a word the reader was no longer pointing at — leaving a fixed-position
  highlight that nothing would clear until the next press.
- **The arrow keys were taken from the browser too eagerly.** They were
  claimed whenever the modifier was held and the pointer had crossed any text.
  That is Alt+Left — Back on Windows and Linux, word-wise caret movement on
  macOS — gone for anyone resting the pointer over an article. They are
  claimed now only once a lookup has happened, so there is a span to reshape,
  and never from a field someone is typing in.
- **A dismissed card could not be reopened.** The last looked-up word was
  remembered until the modifier came up, so returning to the same word did
  nothing at all.

## What did the settings page not save? {#settings}

Ten defects. The three worth reading:

```oku-table
{"headers":["What the reader did","What happened","Why"],"rows":[["Chose the API backend","The bridge address and token stayed on screen","`hidden` is a hint until something says so: `.row { display: flex }` beats the user-agent rule. Measured: 8 elements here, 3 on the popup, 6 on the panel that `hidden` could not hide"],["Pressed Test on a working bridge","\"Reached it, but the token was refused.\"","The token box is cleared on save and this page only ever sees a masked form, so the request went out unauthenticated. The check moved to the worker, where the token lives"],["Set the wait to 0 and pressed Save","It snapped back to 250 with a \"Saved\" flash","`Number(value) || fallback` — a legitimate zero is falsy. Nothing enforced the declared range either, so a sixteen-minute dwell saved happily and stopped the card ever opening"]]}
```

Also: the on-device model row was bound to the first language in the list
rather than the stored one, so a reader whose gloss language is German was
offered a Turkish model and told it was ready; saving wrote a snapshot taken
when the tab opened, silently deleting a per-site rule the popup had created
since; and the translator advice was appended on every language change with
nothing removing the previous copy.

Accessibility: the popup's only control announced as a bare hostname because
the label's whole text was replaced by it, none of the five status surfaces
was a live region, and "Saved" sat in the accessibility tree permanently
because opacity alone does not remove it. The two actions that cannot be
undone now ask first, and removing a dictionary no longer drops keyboard focus
to the body.

## Was anything slow? {#performance}

Measured rather than assumed, and the answer is no.

where it does. Nothing here was changed for speed.

## What did the page look like? {#design}

The settings controls were packed to their own content, so they began at
**twelve different horizontal positions** between 542 and 921 pixels. A reader
scanning the page had to re-find the field on every line, and a missing value
would have hidden in the ragged edge.

What made it ragged was copy in the wrong place. Every model option carried
"per million tokens", which made that one select three times wider than
anything else on the page. The unit is said once now, in the hint beside the
control, and the options carry the numbers. Measured again afterwards: two
positions, three pixels apart.

Four pieces of copy went with it — a number field whose unit was never named,
a hint that opened with a clause about Turkish quality before saying what the
setting did, a capability line that read as a debug print, and a popup that
said "This site: …" beside a disabled control when there was no site.
