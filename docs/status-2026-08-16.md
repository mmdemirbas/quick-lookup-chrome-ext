### Both misses are one defect, and it is the family you reported {#parquet}

Selecting `Parquet` while reading the Iceberg documentation returns an article
about decorative wooden flooring. `Apache Parquet` exists and is exactly the
article wanted. It is never reached. `Second` fails the same way: Wikipedia
has an article titled "Second" about the SI unit, so a sentence-opening
"Second" resolves to a unit of time.

The cause is not the gate I added this morning — it is the path that gate
does not sit on.

```oku-diagram
{"src":"flowchart LR\n    SEL[\"Selection: Parquet\"] --> FAST[\"Fast path: look up the title directly\"]\n    FAST -->|\"found an article\"| RET[\"Return it — wooden flooring\"]\n    FAST -->|\"404 or disambiguation\"| SEARCH[\"Search, biased by page topic\"]\n    SEARCH --> GATE{\"About the selection?\"}\n    GATE -->|yes| GOOD[\"Apache Parquet — never reached\"]\n    TOPIC[\"Page topic: iceberg, table, format\"] -.->|\"only consulted here\"| SEARCH","caption":"The fast path succeeds, so it short-circuits before the page context is ever consulted. Page context only influences the search branch, and the search branch only runs when the direct title lookup fails."}
```

The fast path exists for good reasons — it is one cached request, it
normalises titles, and it is what makes `NYC` resolve to New York City. But it
is completely context-blind, and a common word that happens to name an
unrelated article wins outright. This is the same shape as `Schema` returning
Apache Iceberg, mirrored: there the page context was too strong, here it is
not consulted at all.

> [!NOTE]
> I have not fixed this. It is a separate defect from the two you reported and
> it deserves its own decision, because the obvious fix has a cost: checking
> the biased search *as well as* the direct title means a second request on
> every entity lookup. The narrower fix is to consult the search branch only
> when the direct article's own subject has no overlap with the page topic —
> one extra request in the rare case rather than always. `Alan Turing` on a
> computing-history page would still take the fast path and stop.
